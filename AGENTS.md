# AGENTS.md — Конструктор танцевальных связок

## Что это

Статический клиент для построения библиотеки танцевальных связок (бачата), без сборщика. Основное хранилище — сервер Node.js/SQLite с Google/email-входом, локальный режим сохраняет данные в браузере. Сервер имеет собственные зависимости в `server/package.json`. Ветки: `master`, remote `origin` → `https://github.com/Molostov-A/dance-sequence-builder.git`.

## Запуск и проверка

**Версия файлов.** Все `css/*.css` и `js/*.js` подключены в `index.html` с `?v=<версия>`; та же версия — в `<meta name="app-version">` и `APP_VERSION` (`js/constants.js`). **При каждой правке js/css версию нужно поднять во всех трёх местах**: GitHub Pages разрешает кэш на 10 минут, и без этого браузер берёт новую страницу со старыми скриптами (функции «не работают»). `run-tests.js` проверяет совпадение версий; если страница и скрипты всё же из разных версий, `checkAppVersion()` показывает плашку «обновите страницу (Ctrl+F5)».

Сборки нет. Проверка изменений — открыть `index.html` в браузере (работает и по `file://`, и с GitHub Pages). Проверять нужно вручную:

- десктоп и мобильная ширина ( breakpoints: 900px и 500px);
- переключение всех 6 разделов через боковое меню (кнопка «☰ Разделы»);
- закрепление меню (📌): закреплённое не сворачивается, откреплённое сворачивается по клику вне/`Esc`/потере фокуса;
- оба режима дерева (`⌨` ветка / `⊞` все ветви);
- открытие формы, панорамирование доски, merge ответвлений, генератор, экспорт/импорт.

Синтаксическую проверку JS можно делать так: `node --check <file>` для каждого файла в `js/`.

**`loadState()` выполняется прямо при загрузке `state.js`**, до остальных скриптов. Всё, что она вызывает (все `normalize*`), должно быть объявлено в `state.js`, иначе загрузка падает. `run-tests.js` проверяет это статически; при сбое загрузки сырые данные копируются в `localStorage` под ключом `<STORAGE_KEY>-broken-<время>`.

Автотесты: `node tests/run-tests.js` — копирует проект во временную папку, встраивает `tests/test-suite.js` в `index.html` и гоняет его в headless Chrome (путь можно задать через `CHROME_PATH`). Новые сценарии добавлять в `test-suite.js`; `state` там задаётся вручную, поэтому код должен переживать отсутствие новых полей.

## Архитектура

Глобальная область видимости, без модулей и без `import`. Каждый файл `js/*.js` — скрипт с функциями верхнего уровня, подключённые через `<script>` в `index.html`. **Порядок подключения значим** (зависимости от констант и глобальных переменных на этапе выполнения):

```
constants.js → state.js → beat.js → movements.js → preps.js → picker.js
→ nodes.js → path.js
→ layout.js → treePins.js → form.js → tree.js → combos.js → comboFolders.js → exports.js → panels.js
→ pan.js → generator.js → dictionary.js → media.js → mentions.js
→ sync.js → drive.js → account.js → app.js (инициализация)
```

`js/pan.js` — единственный модуль, обёрнутый в IIFE. Остальные — plain global.

### Разделы (views)

Шесть независимых разделов, одновременно виден ровно один:

| view | id контейнера | `data-view` | функция рендера |
|---|---|---|---|
| Дерево связок | `#view-tree` | `tree` | `renderTree()` |
| Библиотека движений | `#view-library` | `library` | `renderMovements()` |
| Библиотека препов | `#view-preps` | `preps` | `renderPreps()` |
| Комбинации | `#view-combos` | `combos` | `renderCombos()` |
| Генератор | `#view-generator` | `generator` | `renderGenerator()` |
| Словарь | `#view-dictionary` | `dictionary` | `renderDictionary()` |

Переключение — `setView(viewName)` в `js/state.js`. Она снимает `.active` со всех `.view`, ставит его на `#view-<name>`, подсвечивает пункт `.nav-item`, сохраняет состояние и перерисовывает целевой раздел.

Текущий раздел сохраняется в `state.currentView` и восстанавливается при загрузке.

### Боковое меню

Разделы живут в боковом меню `#sidebar` (`.nav-item` — кнопки), открывается/закрывается кнопкой «☰ Разделы» (`#navToggle`). Открытое состояние — класс `nav-open` на `body`, закрепление — `nav-pinned` и `state.navPinned`. Кнопка 📌 (`#btnPinSidebar`) переключает закрепление:

- закреплено — меню не реагирует на клик вне/`Esc`/потерю фокуса;
- откреплено — меню сворачивается при клике вне, `Esc` или уходе фокуса (`focusout`) из `#sidebar`;
- на ширине ≤900px меню становится оверлеем (`position: fixed`, затемнение), закрепление игнорируется, выбор раздела сразу закрывает его.

Логика — в `js/app.js` (`openNav`/`closeNav`/`setNavPinned`), стили — `layout.css` и `responsive.css`.

### Главный цикл рендера

`render()` в `js/app.js` — единственная точка полной перерисовки:

```js
ensureActivePathValid();
renderMovements(); renderPreps(); renderRootsBar(); renderBreadcrumb();
renderTree(); renderCombos(); renderGenerator();
setView(state.currentView);
```

Она рендерит **все** разделы, включая скрытые (дёшево, DOM небольшой). Не нужно оптимизировать выборочный рендер без явной необходимости.

**Правило: любое изменение `state` завершается парой `saveState(); render();`** — в таком порядке. Исключения: `toggleTreeView`/`setView` вызывают точечный рендер + `saveState`.

Импорт — транзакционное исключение: `prepareState()` проверяет отдельный объект; пробный `render()` выполняется с `stateSaveSuspended`, затем вызывается `saveState()`. При ошибке прежнее состояние восстанавливается без записи частичного импорта. `saveState()` возвращает boolean и показывает `#storageBanner` при отказе записи.

## Модель данных

Всё в одном глобальном объекте `state` (`js/state.js`), сохраняется в `localStorage` под ключом `STORAGE_KEY = 'dance-combos-v10'`.

Это ключ гостя. При серверном входе `activeStorageKey` переключается на `STORAGE_KEY + '-user-' + userId`; перед переключением старый контекст сохраняется. Метаданные синхронизации и параметры запасного Drive привязаны к тому же активному ключу. Нельзя автоматически переносить гостевые данные в аккаунт или данные одного аккаунта в другой.

```js
state = {
  movements:   [{ id, name, lead, follow, nameSegments, leadSegments, followSegments }], // библиотека движений
  roots:       [nodeId, ...],                     // корневые узлы
  nodes:       { [id]: { id, movementId, parentId, beat, length, prepId } }, // prepId: null | id препа на линии родитель → узел
  nodeOrder:   [nodeId, ...],                     // порядок вставки, стабильная итерация
  nextNodeId:  1,
  nextMovId:   1,
  activePath:  [rootId, ..., activeId],           // путь от корня до активного узла
  treeViewMode: 'path' | 'all',
  merges:      [{ from: nodeId, to: nodeId }],     // боковые ответвления
  comboVideos: { [comboKey]: [url, ...] },        // видео готовых комбинаций (несколько на связку)
  comboDescriptions: { [comboKey]: text },          // текстовые описания комбинаций
  comboDescriptionSegments: { [comboKey]: segments }, // сегменты описаний (с @-ссылками)
  concepts:    [{ id, short, names, definition, definitionSegments, media }], // словарь
  nextConceptId: 1,                               // генерация id вида 'w<n>'
  currentView: 'tree' | 'library' | 'combos' | 'generator' | 'dictionary',
  navPinned: true,                                 // боковое меню закреплено
  collapsedNodes: [nodeId, ...],                   // узлы со свёрнутыми продолжениями
  preps:       [{ id, name, lead, follow, nameSegments, leadSegments, followSegments }], // библиотека препов
  nextPrepId:  1,
  comboFolders: [{ id, name, parentId }],          // папки комбинаций (дерево, parentId: null — верхний уровень)
  nextComboFolderId: 1,
  comboFolderLinks: { [comboKey]: [folderId, ...] }, // в каких папках лежит комбинация
  collapsedComboFolders: [folderId, ...],          // свёрнутые папки
  looseCombosCollapsed: false,                     // свёрнута группа «Без папки»
  treeHighlight: { folderId, color },              // подсветка папки в дереве (folderId null — нет)
  treePins: { nodes: { [id]: {dx, dy} }, buses: { [parentId]: {dx} }, preps: { ['parentId:prepId']: {dx, dy} },
              links: { [linkKey]: { shape: 'bus', ex } | { shape: 'curve', hx, hy } } },
  collapsedPrepLinks: ['parentId:prepId', ...]     // свёрнутые препы (метка на линии)
}
```

Инварианты, которые нужно сохранять:

- `roots` содержит только id узлов с `parentId === null`.
- `nodeOrder` содержит все существующие id, без дублей.
- `activePath` — непрерывная цепочка `parentId` от корня; проверяется `ensureActivePathValid()`.
- `merges` — не более одной записи на `from`; `addMerge()` сам вытесняет прежнюю.
- Названия движений уникальны без учёта регистра (`addMovement`).

При любом удалении узла обязательно чистить производные структуры: `state.roots`, `state.nodeOrder`, `state.nodes`, `state.merges`, `state.activePath`. Эталон — `deleteNode()` в `js/nodes.js` и `deleteMovement()` в `js/movements.js`.

## Доменные правила (32 счёта = 1 квадрат)

Всё считается в `js/beat.js`. **Не хардкодить числа, а использовать эти функции.**

- `beatInEighth(beat)` = `((beat - 1) % 8) + 1` — позиция внутри восьмёрки, 1..8.
- `eighthNumber(beat)` = `floor((beat - 1) / 8) + 1` — номер восьмёрки, 1..4.
- `isSquareEnd(beat, length)` = `(beat + length - 1) % 32 === 0` — заканчивается ли движение на квадрате.
- `allowedLengths(beat)` — **главное правило валидации длительности**:
  - позиция 1 или 5 → `[4, 2]`
  - позиция 3 или 7 → `[2]`
  - иначе `[]` — движение там начать нельзя.

Если `allowedLengths(beat).length === 0`, кнопку продолжения нужно делать `disabled`. Это уже реализовано в `renderSpineCard()` и `renderFullTreeNode()`.

Формат подписей: `formatBeat()` (длинный, для подсказок), `formatBeatNode()` (`3: 5-8`, для бейджей), `formatBeatShort()` (`5-8`, для генератора).

## Раскладка дерева — двухпроходный алгоритм

`js/layout.js` (чистая геометрия) + `js/tree.js` (рендер). **Это самое хрупкое место проекта.**

Причина двух проходов: названия движений переносятся, поэтому реальная высота карточки (`offsetHeight`) больше константы `CARD_H` и неизвестна до отрисовки в DOM.

Порядок в `renderTree()` (режим `path`):

1. `computeLayout()` с дефолтами — предварительные координаты.
2. Создать DOM-карточки, добавить в `#nodesLayer` с `visibility: hidden`.
3. Замерить реальные `offsetHeight` каждой карточки и мини-карточки.
4. Повторно вызвать `computeLayout({ activeCardH, heightFor, miniHFor })` с реальными высотами.
5. Проставить `left`/`top`, задать размеры `#treeInner` и `#linesSvg`, вернуть `visibility`.

**Не «оптимизировать» это в один проход** — активная карточка начнёт перекрывать стек братьев, а братья выше активного — наезжать на родителя. Та же схема применена в `renderFullTree()`.

Геометрия (комментарии в `layout.js` описывают её подробно):

- **Хребет** — узлы активного пути, кроме активного; горизонтально, `y = PAD`, шаг `CARD_W + H_GAP`.
- **Стек братьев** — все дети родителя активного, сортировка по имени движения (`getChildrenSorted`), вертикально, `x = последний хребет + H_GAP_MINI`. Активный среди них — крупная карточка, остальные — мини.
- **Продолжения активного** — дети активного, столбиком справа, `x = активный + CARD_W + CHILD_H_GAP`.
- Мини-карточки центрируются относительно крупной карточки: `x = stackX + (CARD_W - MINI_W) / 2`.

Линии рисуются в `#linesSvg` (SVG, `createElementNS`) по координатам из того же layout. Цветовая семантика:

| Цвет | Смысл |
|---|---|
| `#3498db` | основной поток дерева |
| `#b8c4cf` пунктир | шина стека братьев |
| `#7fbf7f` | ответвления активного узла (продолжения) |
| `#9b59b6` пунктир | merge-связи |

Константы геометрии — в `js/constants.js` (`CARD_W`, `CARD_H`, `MINI_W`, `MINI_H`, `H_GAP`, `H_GAP_MINI`, `CHILD_H_GAP`, `BUS_OFFSET`, `PAD`, `STACK_OFFSET`). Правки разметки почти всегда означают правку констант, а не хардкод чисел в разметке.

`renderTree()` сохраняет и восстанавливает `scrollLeft`/`scrollTop` — панорамирование не должно сбрасываться при перерисовке.

### Сворачивание продолжений

На правой кромке каждой крупной карточки с детьми — кнопка `−` / `+N` (`renderCollapseToggle()` в `tree.js`), N — число скрытых потомков. Свёрнутые id хранятся в `state.collapsedNodes`; раскладка берёт детей через `getVisibleChildren()` (`nodes.js`), поэтому свёрнутый узел раскладывается как лист в обоих режимах. На данные, комбинации и генератор не влияет.

- `toggleCollapse()` при сворачивании предка активного узла переносит активность на свёрнутый узел.
- `setActiveNode()` разворачивает предков выбранного узла (переход из крошек/стартов).
- При удалении узлов чистить и `collapsedNodes`; при загрузке/импорте — `normalizeCollapsedNodes()`.

## Препы на линиях

`js/preps.js`. Преп — переходный мостик между движениями, отдельная библиотека `state.preps` (раздел «Библиотека препов»). Преп стоит **на линии** родитель → узел и хранится в ребёнке как `node.prepId` (у узла ровно одна входящая линия). Счётов не занимает, правила 32 счётов и `allowedLengths` не меняются. У корня `prepId` всегда `null`.

- `getChildrenSorted()` ставит сначала детей без препа, затем группы по препу — группы идут подряд. Поэтому из одного движения за одним препом может выходить несколько продолжений, и в дереве они рисуются за **одним** блоком препа.
- Раскладка (`layout.js`, п. 5): если у кого-то из детей колонки есть преп, колонка сдвигается на `PREP_COL`, блоки препов (`prepChipsForColumn`) встают в этот промежуток, по одному на группу, по центру группы. На хребте промежуток перед узлом с препом тоже расширяется на `PREP_COL`. Высота блока фиксирована (`PREP_H`), поэтому в двухпроходной схеме его не замеряют.
- Линии — `drawFanOut()` в `tree.js`: отводы с шины родителя к детям без препа и к левому краю блоков препов; от правого края блока — своя короткая шина к детям группы. Используется в обоих режимах (стек братьев, продолжения активного, полное дерево).
- Блок препа (`renderPrepChip`) лежит поверх линии (z-index ниже карточек). Клик по названию — редактирование препа; кнопки при наведении: `+` — продолжение за этим препом (`openForm({ ..., prepId })`), `–` — свернуть, `✕` — убрать преп со всех связей группы (`removePrepFromLink`).
- Незакреплённый блок препа стоит посередине своей линии: между шиной (общей или собственным изломом линии к препу) и колонкой детей (`centerPrepChip`, `chip.colX`). Закреплённый стоит где поставили, линии подстраиваются под него; если до детей не хватает места на короткую шину, от блока к каждому ребёнку идёт прямая.
- Свёрнутый преп (`state.collapsedPrepLinks`, ключ `parentId:prepId`) — круглая метка `‖` размером `PREP_MARK`; колонка детей отодвигается только на `PREP_MARK_COL`. Кнопка `‖` в шапке дерева сворачивает/разворачивает все (`toggleAllPrepLinks`). Размеры — `prepChipGeometry()`, у блока есть `subX` (x короткой шины группы).
- Преп на исходящей связи нового движения: кнопка `‖` на активной карточке («Продолжить через преп» — выбрать/создать преп, затем форма продолжения) или строка «Преп на линии» в форме.
- Кнопки на самих связях: у каждой связи есть невидимая хит-линия (`svgHit`, `data-link-key`, у линии к ребёнку ещё `data-link-child`); при наведении появляется плашка `#linkControls` (в `#treeInner`, вне `#nodesLayer`): «‖ Добавить преп» или «⇄ Сменить преп» / «✕ Убрать преп», на линии к блоку препа — «✕ Убрать преп» для всей группы, в полном дереве — ещё форма связи. Участки через преп несут `data-prep-id` — при наведении `#prepTooltip` показывает название, лид и фоллоу (`initPrepTooltip`).
- В комбинациях преп показывается между шагами (`comboStepPrep`): только если предыдущий шаг — родитель узла; переход по merge препа не имеет. В `exportCombos()` — поле `step.prep`. Ключ видео/описаний преп не включает.
- Миграция (`normalizePreps` в `state.js`): старое `node.preparation = { movementId }` копируется в библиотеку препов (без дублей по имени) и ставится на все **исходящие** линии узла — детям без своего препа. У листа такая подготовка теряется.
- `deletePrep()` снимает преп со всех линий. Препы участвуют в `collectConceptUsage`/`replaceConceptReferences`/`pruneMentions` наравне с движениями.

## Ручная раскладка: перетаскивание и закрепление

`js/treePins.js`, только режим «все ветви». Карточку, блок препа и вертикальную шину родителя можно перетаскивать мышью/пальцем (pointer-события, порог `DRAG_THRESHOLD`; меньший сдвиг — обычный клик). Перетаскивание само закрепляет элемент в `state.treePins`:

- карточка — смещение левого верхнего угла от родителя (корень — от холста);
- блок препа — смещение от родителя; шина — отступ от правого края родителя.

**Форма связей.** По умолчанию связи идут по общей шине родителя. Ключ связи: `c:<ребёнок>` — линия к ребёнку (от родителя или от блока его препа), `p:<родитель>:<преп>` — линия от родителя к блоку препа (дети с общим препом сходятся в преп и одной линией идут к родителю). `drawFanOut()` рисует связи с записью в `treePins.links` отдельно: `bus` — своя шина с изломом на `ex` от точки выхода (перетаскивание отрезка двигает излом, форма остаётся шиной); `curve` — кубическая кривая через ручку `.curve-handle`, смещённую на `(hx, hy)` от середины линии (контрольные точки сдвигаются на 4/3 смещения, чтобы кривая шла ровно через ручку). Форма переключается кнопками на связи «⌒ Изгиб» / «┐ Шина», «↺ Авто» и 📌 у связи возвращают её на общую шину.

`applyTreePins()` в `layout.js` применяет закрепления после автоматической раскладки сверху вниз: незакреплённые элементы сдвигаются вместе с родителем, поэтому ветка едет за перенесённым узлом. Шина не уходит правее своих отводов; всё, что ушло левее/выше `PAD`, возвращается на холст. Закреплённые элементы получают кнопку 📌 — открепить (вернуть авто-положение); `↺` в шапке открепляет всё. Во время перетаскивания закрепление пишется сразу и перерисовывается только дерево (`requestAnimationFrame`), слушатели висят на `window` (DOM дерева пересоздаётся); клик, завершивший перетаскивание, гасится. `lastFullLayout` — последняя раскладка полного дерева (стартовые позиции). `normalizeTreePins()` (в `state.js`) вызывается при загрузке, импорте и в каждом `render()` — чистит закрепления удалённых узлов и групп препов. При смене родителя закрепление узла сбрасывается.

## Окно выбора, замена движения, смена родителя

`js/picker.js` — общее окно `#libraryPickerModal` (`openLibraryPicker(opts)`): поиск, прокручиваемый список, пометка текущего, необязательные «Без …» сверху и «+ Новый …» снизу. Enter выбирает точное или единственное совпадение, а при отсутствии совпадений — создаёт.

- Замена движения (`⇄`, `replaceMovement()` в `nodes.js`) — выбор из библиотеки или создание нового через `openMovementModal({ text, onSaved })`.
- Модалка движения общая для движений и препов: `openMovementModal({ kind: 'prep', prepId })` / `{ kind: 'prep', text, onSaved }`.
- Смена родителя: `⤴` на активной карточке (`openChangeParentPicker`) — выбрать новому узлу родителя; `⤵` (`openAdoptChildPicker`) — то же со стороны родителя: забрать к себе чужой узел. Оба вызывают `reparentNode()`: узел переезжает с поддеревом, счёты ветки сдвигаются. `canReparent()` пускает только цель, после которой продолжение начинается в той же позиции восьмёрки (сдвиг кратен 8, длительности остаются допустимыми), и запрещает переезд к себе, к потомку и к нынешнему родителю. Преп входящей линии переезжает вместе с узлом. Merge, ставшие петлёй, удаляются; видео/описания затронутых комбинаций отвязываются (с подтверждением).

## Переход к комбинациям

Кнопка `≡` на активной карточке — `showCombosForNode(nodeId)` в `combos.js`: открывает «Комбинации» с фильтром по узлу (переменная модуля `comboFocusNodeId`, в `state` не сохраняется). Плашка сверху: «← К узлу в дереве» и «Показать все». Номера `#N` остаются общими.

## Форма добавления

`js/form.js`. `#formLayer` — абсолютно позиционированный слой **поверх дерева**, не внутри `.view`.

- «Из библиотеки» — строка поиска `.mov-search` над списком: `searchWordsMatch()` (в `picker.js`) ищет каждое слово отдельно, без учёта регистра и ё/е. Пока введён текст, список раскрыт, показывает только совпадения и выбирает первое; без совпадений — кнопка «+ Создать «…» как новое движение» переносит текст в поле нового движения. Тот же поиск по словам — в общем окне выбора (`openLibraryPicker`).
- Состояние формы — `openFormState = { parentId, isRoot, beat, prepId }` (глобальная переменная модуля). `prepId` — преп на линии к новому узлу; строка препа обновляется на месте (`updateFormPrepRow`), без перестройки формы.
- `buildForm()` не перестраивает DOM, если сигнатура `formSignature()` не изменилась.
- `positionForm()` привязывает форму к карточке родителя через `getBoundingClientRect()`, затем клампит в пределы окна. На ширине ≤900px форма становится `position: fixed` шторкой снизу (см. `responsive.css`), и JS сбрасывает координаты.
- После любого `render()`: если форма открыта — перестроить, если слой пуст, иначе `positionForm()`.

## Модальное окно движения

`js/movements.js`. `openMovementModal({ movementId })` открывает редактирование существующего движения: название, поля `lead` и `follow` («что делает лид/фоллоу»). Точки входа — строка библиотеки, кнопка ✎ в форме добавления и кнопка ✎ на карточке любого полного узла дерева (`renderCardTitle()` в `tree.js`). `openMovementModal({ text, lead, follow, onSaved })` редактирует черновик, который ещё не добавлен в библиотеку (кнопка ✎ у поля «Новое движение»); данные черновика хранятся в скрытых полях формы и применяются при `submitForm()`.

Сохранение проверяет непустое имя и уникальность без учёта регистра. Если форма добавления открыта, её option обновляется через `syncFormMovementOption()`; сама форма при этом не перестраивается, чтобы не терять выбранные значения.

Разметка — `#movementModal` в `index.html`, стили — `modal.css`. Описания также попадают в tooltip карточек и в экспорт комбинаций (`lead`/`follow` в шагах).

## Боковые ответвления (merge)

`js/nodes.js`. Прямолинейное дерево плюс неявные переходы между узлами.

- `findMergeTargets(fromNodeId)` — цель должна: начинаться в той же позиции восьмёрки, не быть предком источника, не быть самим источником; `nextBeat` источника должен быть ≤ 32.
- `state.merges` — максимум одна запись на `from`.
- `mergeSelectFrom` — глобальная переменная модуля, режим выбора цели. Цели получают класс `.merge-target` и переопределённый `onclick`; клик мимо карточек отменяет выбор.
- Merge учитывается в `collectCombos()` — `walk()` продолжает обход по merge-цели.
- При удалении узла или движения чистить `state.merges` по обоим концам.

## Комбинации

`js/combos.js`. Листовые пути дерева: `collectCombos()` обходит DFS от каждого корня; узел считается листом, если нет детей **и** нет merge-цели. `visited` защищает от циклов через merge.

### Видео комбинации

Кнопка «+ Видео» / «▶ Видео (N)» в строке комбинации открывает модальное окно `#comboVideoModal`. На связку можно добавить несколько видео: список ссылок в `#comboVideoList` (каждая строка — URL + предпросмотр + удаление), кнопка «+ Добавить видео». Ссылки хранятся в `state.comboVideos[comboVideoKey(combo)]` как **массив строк**; ключ `comboVideoKey(combo)` — последовательность `nodeId:movementId:beat:length`, склеенная `|`. Ключ меняется при изменении состава, движения или длительности, поэтому старые видео не привязываются к изменившейся связке. `normalizeComboVideos()` (в `state.js`) приводит старые значения-строки к массивам `[url]`; `pruneComboVideos()` удаляет осиротевшие записи.

Поддерживаются ссылки Google Диска на файл: `/file/d/<id>/...` и `?id=<id>`. Они преобразуются в `https://drive.google.com/file/d/<id>/preview` для встроенного iframe; кнопка «Открыть в новой вкладке» ведёт на `/view`. Файл должен быть доступен по ссылке, иначе Google покажет запрос доступа внутри iframe. Ссылки на папки и другие хосты отклоняются. Разметка — в `index.html`, стили — `combo.css` и `modal.css`, события — `app.js`.

### Описание комбинации

Кнопка «+ Описание» / «✎ Описание» в строке комбинации открывает `#comboDescriptionModal` с contenteditable-полем (поддерживает @-упоминания). Текст хранится в `state.comboDescriptions[comboKey]`, сегменты — в `state.comboDescriptionSegments[comboKey]` (тот же ключ `comboVideoKey`). Описание показывается под последовательностью комбинации через `renderRichText`. Пустое описание удаляется. `pruneComboDescriptions()` чистит осиротевшие ключи; `pruneMentions()` чистит @-ссылки в описаниях. В `exportCombos()` добавляется поле `description`. Логика — в `js/combos.js`, стили — `combo.css` и `modal.css`.

### Папки комбинаций

`js/comboFolders.js`. Папки вложенные (`state.comboFolders`, `parentId`), а комбинация может лежать в нескольких папках сразу — как метки. Привязка `state.comboFolderLinks[comboVideoKey(combo)]`, то есть тот же ключ, что у видео и описаний: при изменении состава связки привязка отпадает (`pruneComboDescriptions()` чистит и её). `reparentNode()` предупреждает и о папках.

- `renderCombos()` строит записи `{ combo, idx, key }` (с учётом фильтра по узлу) и отдаёт их в `renderComboFolderTree()`; одна строка комбинации — `renderComboItem()`. Без папок — обычный плоский список; с папками — дерево папок (подпапки, затем свои комбинации) и группа «Без папки» внизу. Комбинация показывается в каждой своей папке; номер `#N` общий. При фильтре по узлу пустые папки скрываются.
- Подсветка в дереве: панель «Подсветка папки» вверху вкладки дерева (`#treeHighlightBar`) — папка (или «Без подсветки») и цвет. `highlightedNodeIds()` собирает узлы всех комбинаций папки и её подпапок; `renderTree()` считает их в начале (`treeHighlightIds`), карточки и мини-карточки обоих режимов получают `.folder-highlight` и `outline` выбранного цвета (`applyFolderHighlight`). Удаление папки снимает подсветку.
- Группа «Без папки» тоже сворачивается (`state.looseCombosCollapsed`, `toggleLooseCombosCollapsed`).
- Шапка папки: сворачивание (`collapsedComboFolders`), счётчик разных комбинаций поддерева, «+» подпапка, ✎ переименование прямо в шапке (`comboFolderEditingId`; Enter/потеря фокуса — сохранить, Esc — отмена), ⇱ перенос в другую папку или в корень (через `openLibraryPicker`, в собственные подпапки нельзя), ✕ удаление вместе с подпапками (комбинации остаются).
- Кнопка «📁» в строке комбинации открывает `#comboFoldersModal`: дерево папок с галочками и поле для новой папки (сразу отмечается).
- `normalizeComboFolders()` (загрузка и импорт) отбрасывает битые записи, разрывает циклы родителей, чистит ссылки на несуществующие папки. В `exportCombos()` у комбинации есть `folders` — пути папок.

### Одинаковые видео

Одно и то же видео может быть прикреплено к нескольким комбинациям. В окнах видео узла и движения такие привязки объединяются: `videoIdentity(url)` — embed-адрес файла Google Диска (разные формы ссылки на один файл совпадают), `pushGroupedVideo()` собирает записи `{ url, key, combos: [...] }`. Видео показывается одной строкой, под ним — блоки `.video-combo-block` со всеми комбинациями, где оно есть. Счётчики `▶N` считают разные видео.

### Видео у узла дерева

`renderTree()` начинает с `rebuildNodeVideoIndex()`: он проходит по `collectCombos()` и считает, сколько разных видео встречается у каждого `nodeId` (одинаковые из разных комбинаций — одно). Если счётчик больше нуля, на карточке (и на мини-карточке) появляется кнопка `▶` (при нескольких видео — `▶N`); клик открывает компактное окно `#nodeVideosModal`. В нём показано место узла (`formatBeat`, например «2-я восьмёрка, 1-4») и список видео, в которых участвует именно этот узел (по одной строке на видео). Выбор строки переключает iframe; кнопка открывает выбранное видео в новой вкладке. Повторный `render()` пересчитывает индекс, поэтому привязка/удаление видео сразу обновляет кнопки. Логика — в `js/combos.js`, разметка — `index.html`, стили — `modal.css` и `tree.css`.

### Видео движения в библиотеке

`renderMovements()` начинает с `rebuildMovementVideoIndex()` в `js/combos.js`. Индекс проходит по комбинациям с видео и для каждого `movementId` собирает записи по видео: одна запись — одно видео, внутри `combos` — комбинации с ним, у каждой `places` — все позиции этого движения в комбинации (на связку может быть несколько видео). Поэтому если движение повторяется в комбинации дважды, у каждого видео этого движения будет два места.

Если у движения есть видео, в строке библиотеки появляется кнопка `▶`/`▶N` (N — число видео, не число вхождений). Она открывает `#movementVideosModal`: сверху iframe, ниже список видео. В каждом пункте — видео и под ним все его комбинации: номер, места (`formatBeat`, например «1-я восьмёрка, 1-4» и «2-я восьмёрка, 1-4») и последовательность движений. Выбор пункта переключает видео. Логика — в `js/movements.js`, разметка — `index.html`, стили — `library.css` и `modal.css`, события — `app.js`.

## Словарь и @-упоминания

`js/dictionary.js`, `js/media.js`, `js/mentions.js`.

### Словарь (понятия)

Пятый раздел `#view-dictionary`. `state.concepts` — массив понятий:

```js
{ id: 'w3', short: 'ок', names: ['Волна','Октава'],
  definition: '…', definitionSegments: [ {text:'…'}, {conceptId:'w1'} ],
  media: [ { type:'image'|'video', url, label } ] }
```

- `short` — единственное и уникальное (без учёта регистра), редактируемое; `id` генерируется как `w<nextConceptId>` и не меняется.
- `names` — варианты полного названия; поиск идёт по `short` + всем `names`.
- `media` — ссылки на картинки/видео (YouTube или Google Drive), открываются в `#mediaModal` через iframe (`parseMediaUrl` в `js/media.js`: YouTube `watch/shorts/embed/live/youtu.be` → `embed/<id>`, Drive `file/d/<id>`/`?id=` → `/preview`).
- CRUD — модалка `#conceptModal`. Удаление (`deleteConcept`) сканирует использования (`collectConceptUsage`) и, если они есть, предлагает замену (`#conceptDeleteModal`): другое понятие или текст — применяется ко всем вхождениям (`replaceConceptReferences`).

### @-упоминания (гиперссылки)

Имя движения (`name`), поля «Лид»/«Фоллоу» и определение понятия хранятся как **сегменты** параллельно обычной строке:

```js
movement.nameSegments = [ { text:'Волна через ' }, { conceptId:'w3' } ]
movement.name = conceptTextFromSegments(movement.nameSegments) // производная строка
```

`movement.name` остаётся обычной строкой — сортировка, сигнатура генератора, экспорт комбинаций не меняются. Аналогично `leadSegments`/`followSegments` и `concept.definitionSegments`.

- Редактор — contenteditable (`makeMentionEditor` в `js/mentions.js`). Ввод `@` открывает `#mentionModal` (автофокус на поле поиска), фильтр по `short`+`names`, выбор вставляет `short` как `<span class="mention" data-concept-id>`, backspace удаляет как обычный текст, правка символа ссылки превращает её в обычный текст (`normalizeMentions`).
- Рендер ссылок — `renderRichText(segments, container)`; применяется в дереве, комбинациях, библиотеке, генераторе. Тултип — `#mentionTooltip` (показывается при наведении на `.mention`, содержит short/варианты/определение/медиа-кнопки; делегирование в `initMentionTooltip`).
- Чистка «битых» ссылок — `pruneMentions()` (вызывается при импорте и на старте).
- Экспорт/импорт: `concepts`, `nextConceptId` и все `*Segments` попадают в `exportAll()` автоматически (`{...state}`); `importJson()` добавляет дефолты и `pruneMentions()`.

## Генератор

`js/generator.js`.

- `extractPatterns()` строит словарь переходов: ключ `movementId:beatInEighth` → список продолжений `nextMovementId:nextBeatPos`.
- `generateSequences()` — рекурсивный обход от счёта 1, на каждом шаге движение берётся из паттернов, длина — из `allowedLengths()`.
- Результат принимается только если: сумма длин **ровно 32** и есть хотя бы один `isSquareEnd`.
- Дедупликация против существующих комбинаций по сигнатуре `movementId:beatInEighth:length`, склеенной `|`.
- Лимит `GEN_MAX_COMBOS = 1000`.
- `genSequences` и `genSelectedIdx` — глобальные переменные модуля, **в `state` не входят и не сохраняются**. После перезагрузки страницы генератор пуст.
- Фильтры над списком (`genFilters`, тоже только в памяти) оставляют **лучшие** связки, а не «все, где что-то есть» (иначе галочка почти ничего не меняла): «Максимально разнообразные» — доля разных движений (`unique / шагов`) равна наибольшей среди сгенерированных; «Новые сочетания движений» — наибольшая доля (`novelty`) цепочек из трёх движений подряд, которых нет ни в одной готовой комбинации (`existingMovementTriples`). Пары «движение → движение» для новизны не годятся: генератор берёт их из дерева. Сначала применяется разнообразие, затем новизна к оставшимся; список сортируется по новизне, затем по разнообразию; `#N` — номер в полном списке. Строка над списком объясняет отбор (`genFilterNote`), в том числе «все одинаково разнообразны» и «новых сочетаний нет». Метки у связки: «разных N/M», «новых сочетаний K из T» (`genSequenceStats`, `genVisibleSequences`).
- `expandSequenceToTree(idx)` создаёт новый корень и линейную цепочку, выставляет `activePath` на последний узел.

## Экспорт / импорт

`js/exports.js`.

- `exportAll()` — весь `state` без `activePath`.
- `exportCombos()` — производные комбинации с детальными данными по каждому шагу; поле `videoUrl` берётся из `comboVideos`.
- Файлы: `dance_combos_<timestamp>.json`, `dance_combos_combos_<timestamp>.json`.
- `importJson()` требует `movements`, `nodes`, `roots`; восстанавливает недостающие `nodeOrder`, `nextNodeId`, `nextMovId`, `activePath`, `merges`, `comboVideos`, `concepts`, `nextConceptId`, `treeViewMode`. После импорта — `pruneComboVideos(); pruneMentions(); ensureActivePathValid(); saveState(); render();`.
- Импорт запускается через `#importModal` (кнопка «Импорт» в шапке): два способа — «Локальный файл» (открывает системный диалог выбора файла, как раньше) и «По ссылке» (поле для URL + `fetch`). `applyImportedJson(text)` — общая точка применения данных для обоих способов. `normalizeImportUrl()` превращает ссылку Google Drive (`/file/d/<id>` или `?id=<id>`) в `https://drive.google.com/uc?export=download&id=<id>`; `importFromUrl()` загружает и применяет JSON.
- Есть резервный путь: если автоскачивание не сработало, показывается модальное окно `#exportModal` с текстом для ручного копирования.

## Облачная связь

Основная синхронизация — `js/account.js` и HTTP API в `server/`. Конфигурация VPS и протокол описаны в `SERVER_SETUP.md`; целевой домен `dance-sequence-builder.duckdns.org`. Cookie сессии HttpOnly; `X-Account-ID` сверяется с текущей серверной сессией, а запись требует Origin + CSRF. Пользовательский ID из тела/URL не определяет владельца данных.

На GitHub Pages `js/runtime-config.js` выбирает API VPS. Для разных origins используются точный CORS origin, bearer-сессия браузера и одноразовый Google return-code с PKCE; на VPS остаются HttpOnly cookie. Подробности — `AUTO_DEPLOY.md`. Workflow `deploy.yml`: проверки → сервер → Pages при push в master; ключ Actions ограничен принудительным deploy-обработчиком. В архивы и Pages не включать секреты и базу.

SQLite обновляется с проверкой revision в одной транзакции, конфликт возвращает HTTP 409. `saveState()` ставит серверное сохранение в очередь через `onAccountStateSaved()`; `accountApplying` запрещает обратную запись загружаемого снимка. Все ответы асинхронных операций проверяются на смену контекста аккаунта. Серверная валидация использует те же `state.js` и `beat.js` в VM без исполнения пользовательского кода.

Проверки: `npm test` в `server/`, `node tests/run-tests.js`, `node tests/server-browser-smoke.mjs`. Последний запускает настоящий API и SQLite с изолированным браузером; почта перехватывается в памяти. Секреты хранятся в игнорируемом `server/.env`, не в клиентском JS. При серверном режиме Drive — запасной вариант, его фоновая запись выключена.

`js/drive.js` — опциональная связь с Google Drive API через Google Identity Services и Google Picker, разрешение `drive.file`. SDK загружаются только при открытии `#driveModal`, на HTTPS/localhost. Настройка описана в `GOOGLE_DRIVE_SETUP.md`.

Общие браузерные реквизиты задаёт владелец в `GOOGLE_DRIVE_CONFIG` (`constants.js`) перед публикацией; тогда настройки в пользовательском окне скрыты. Пустая конфигурация оставляет запасной ввод реквизитов в текущем браузере. Client secret в клиентский код не добавлять.

Параметры связи (Client ID, браузерный API key, номер проекта, ID файла, версия, базовый SHA-256) хранятся отдельно под ключом `STORAGE_KEY + '-google-drive'`. OAuth-токены — только в памяти. `saveState()` после успешной локальной записи вызывает `onDriveStateSaved()`, облачная запись откладывается на 1200 мс. `driveApplying` исключает обратную запись загружаемых данных. `applyImportedJson(text, { confirmReplace, reportError })` используется для применения облачного снимка; по умолчанию обычный импорт сохраняет подтверждение и сообщения об ошибках.

Перед PATCH сравнивается версия Drive; при наличии ETag используется `If-Match`. Конфликт не разрешается автоматически. Изменение состояния во время запроса не должно теряться; базовый хеш соответствует отправленному снимку, а не более свежему `state`. При новом запуске файл помнится, но OAuth инициируется только кнопкой. Тесты — `tests/drive-suite.js`, SDK и API в них подменены.

## CSS

Файлы подключены в `index.html` именно в таком порядке. `responsive.css` идёт предпоследним, чтобы переопределять базовые правила; `generator.css` замыкает список, но не пересекается с `responsive.css` по селекторам.

```
base.css → layout.css → library.css → tree.css → form.css
→ combo.css → modal.css → responsive.css → generator.css
```

- Только обычные hex-цвета, без переменных и препроцессоров.
- `* { box-sizing: border-box }`; `body` — flex-колонка, `overflow: hidden`, `html/body` на 100% высоты. Полноэкранная компоновка, страница не скроллится — скроллятся внутренние контейнеры.
- Файлы разделены по фичам, а не по общей категории.
- **Осторожно с `header button`** в `base.css` — это глобальный селектор для всех кнопок хедера. Новые кнопки в хедере переопределяют его локальными правилами (см. `.nav-btn`).
- Мобильные брейкпоинты: `900px` (основной) и `500px` (узкие). Новые адаптивные правила добавлять в `responsive.css`.

## Соглашения по коду

- Отступ 2 пробела, точка с запятой, одинарные кавычки в JS.
- `const` для констант, `let` для изменяемого состояния.
- Имена функций — camelCase, DOM-идентификаторы — тоже camelCase.
- DOM строится через `document.createElement` + **`textContent`**. Названия движений приходят от пользователя — не подставлять их через `innerHTML`.
- SVG — через `document.createElementNS('http://www.w3.org/2000/svg', ...)`.
- Пользовательский интерфейс, тексты и сообщения — на русском.
- Комментарии в проекте есть, и они несут объяснение **почему** так, а не пересказ кода (см. длинные блоки в `layout.js` и `tree.js` про шины и два прохода). Такие комментарии обязательны для нетривиальной геометрии.

## Git

- Ветка `master`, коммиты и сообщения — на русском, описательные: что изменилось, а не «фикс».
- Коммиты делать только по явной просьбе; в `git add` добавлять только нужные файлы.
- `.vscode/`, `.kilo/`, `server/node_modules/`, `server/.env` и файлы SQLite исключены через `.gitignore`; не добавлять их в коммит.
- `.kilo/worktrees/` — устаревшая копия проекта, исключена локально через `.git/info/exclude`. Не редактировать и не коммитить; там нет `generator.js` и `pan.js`.

## Известные мелочи

- `js/panels.js` содержит только пустые заглушки `applyPanelState()` и `togglePanel()` — остаток от прежней системы сворачиваемых панелей. Можно удалить вместе со ссылками и константой `PANEL_STATE_KEY` в `constants.js`.
- `render()` вызывает рендер всех разделов, а `setView()` дополнительно перерисовывает целевой — двойной рендер одного раздела. На текущих объёмах незаметно.
- Поля имени/лида/фоллоу и определения — contenteditable (`js/mentions.js`), самое хрупкое место. Проверять: ввод `@`, вставку, backspace внутри ссылки, IME, Enter (в однострочном поле не должен переносить строку).
- Тултип карточки в дереве (`movementNotes`) собирается из `lead`/`follow` как обычная строка — @-ссылки внутри него не подсвечиваются (подсветка есть в имени движения).
