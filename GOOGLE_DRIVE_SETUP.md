# Связь с Google Диском без сервера

В основной серверной версии это запасной вариант: окно открывается через **Аккаунт и сохранение → Дополнительно: Google Диск**. Серверный вход Google настраивается отдельно по `SERVER_SETUP.md` и не требует Google Drive API. В серверном режиме фоновая запись Drive отключена, синхронизация запускается явно.

В приложении есть отдельная кнопка **☁ Google Диск**. Она связывает приложение с существующим JSON-файлом через официальный Google Drive API. Публичная ссылка на скачивание для этого не используется: файл можно оставить закрытым.

## Однократная настройка владельцем приложения

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и создайте или выберите проект. Все следующие настройки должны относиться к одному проекту.
2. В **APIs & Services → Library** включите **Google Drive API** и **Google Picker API**.
3. В **Google Auth Platform** настройте название приложения и контактный email. Для личного использования можно оставить аудиторию External / Testing и добавить свой Google-аккаунт в список тестовых пользователей.
4. В разделе доступа к данным добавьте разрешение `https://www.googleapis.com/auth/drive.file`. Оно даёт приложению доступ только к файлам, которые пользователь выбрал для него через Google Picker; весь Диск приложение не запрашивает.
5. Создайте **OAuth client** типа **Web application**. В **Authorized JavaScript origins** добавьте `https://molostov-a.github.io` — без `/dance-sequence-builder/` и без завершающего пути. Для локальной разработки можно дополнительно добавить точный адрес, например `http://localhost:8080`. Скопируйте **Client ID**, заканчивающийся на `.apps.googleusercontent.com`.
6. Создайте браузерный **API key**. Ограничьте его API **Google Picker API** и **Google Drive API**. В ограничениях сайтов укажите `https://molostov-a.github.io/*` и `https://docs.google.com/*`; последний адрес нужен iframe Google Picker. Для разработки добавьте свой `http://localhost:8080/*`.
7. На главной странице проекта скопируйте **Project number** — числовой номер проекта, не текстовый Project ID.
8. Перед публикацией заполните `GOOGLE_DRIVE_CONFIG` в `js/constants.js`: `clientId`, `apiKey`, `projectNumber`. Поднимите версию ресурсов по правилам проекта и опубликуйте приложение. Эти настройки общие: обычным пользователям вводить их не нужно, раздел настройки в интерфейсе скрывается. **Client secret не нужен** и в браузер не вводится.

Для проверки без изменения общих настроек можно ввести эти три значения в **☁ Google Диск → Настройка Google Cloud**: они сохранятся только в текущем браузере. Это запасной режим владельца для настройки проекта.

Приложение по `file://` продолжает работать локально, но для OAuth нужно открыть версию HTTPS или localhost из разрешённых origins. Настройки, опубликованные в `GOOGLE_DRIVE_CONFIG`, действуют для всех устройств. Эти браузерные идентификаторы не являются секретом серверного клиента. Ограничения API key задаются в Google Cloud.

## Как связать существующий файл

1. Сначала при необходимости сделайте локальный бэкап кнопкой **Экспорт всего**.
2. Нажмите **☁ Google Диск → Подключиться**, войдите в аккаунт Google и разрешите доступ к выбранному файлу.
3. В окне Google выберите свой `dance_combos_….json`. В аккаунте должно быть право изменять этот файл. Для файла из вопроса выберите `dance_combos_2026-11-10_19-01-02.json`.
4. Подтвердите загрузку облачных данных в приложение. Только после успешной проверки и локального сохранения приложение запомнит связь.
5. Дождитесь статуса **Синхронизировано**. Изменения библиотеки и дерева сохраняются в тот же файл с задержкой около 1,2 секунды, чтобы не отправлять запрос на каждое нажатие.

Файл нужно выбрать через Google Picker: вставленная ссылка сама по себе не выдаёт разрешение `drive.file`. Повторно выбирать файл при обычном запуске не нужно — приложение помнит его ID и название.

## Повторный запуск и потеря связи

- Сразу открывается локальная сохранённая копия, а рядом с кнопкой облака появляется **Нужно подключиться**.
- Нажмите **Подключиться**. Если изменился только облачный файл, он загрузится; если изменились только данные на устройстве, они отправятся в облако.
- Если изменились обе версии, запись приостанавливается. Можно **Загрузить облачную версию** или **Сохранить мою версию в облаке**. Обе замены требуют явного подтверждения. Перед выбором можно сделать экспорт.
- Раз в минуту при открытой странице проверяются изменения облачного файла. Это синхронизация целого JSON, без автоматического объединения отдельных движений.
- Если пропал интернет или истёк доступ Google, изменения остаются в `localStorage`. При следующем подключении проверяется версия файла перед записью. Локальное переключение разделов и навигация в файл не отправляются.
- OAuth access token хранится только в памяти вкладки. Его нет в `localStorage`, экспорте и коде проекта. После перезагрузки или истечения токена нужен пользовательский клик для обновления доступа; без сервера это ожидаемое поведение Google Identity Services.
- **Отвязать файл** отключает связь в браузере, сохраняя локальные данные и файл на Диске.

Перед записью приложение сравнивает версию Drive и, если сервер возвращает ETag, передаёт `If-Match`. Это предотвращает обычное перетирание версии, изменённой на другом устройстве. Без ETag проверка версии не является распределённой блокировкой: строго одновременное редактирование на нескольких устройствах лучше избегать.
