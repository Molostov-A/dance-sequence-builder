# Конструктор танцевальных связок

**Живая демонстрация (GitHub Pages):** https://molostov-a.github.io/dance-sequence-builder/

Одностраничное приложение для построения библиотеки танцевальных связок (бачата): дерево связок, библиотеки движений и препов, готовые комбинации, генератор связок и словарь понятий. Основной режим — аккаунт с серверным хранением и локальным кэшем. Клиент не требует сборки; локальная версия и GitHub Pages продолжают работать с данными браузера.

## Запуск

Серверная версия: https://dance-sequence-builder.duckdns.org. Развёртывание на Ubuntu 24.04 описано в [SERVER_SETUP.md](SERVER_SETUP.md), автоматическое обновление сервера и Pages — в [AUTO_DEPLOY.md](AUTO_DEPLOY.md).

Для локального режима достаточно открыть `index.html`. GitHub Pages подключается к API на VPS; на самом VPS клиент использует свой origin.

## Разделы

Шесть независимых разделов переключаются в боковом меню (кнопка «☰ Разделы»). Кнопка 📌 закрепляет меню: закреплённое не сворачивается, откреплённое — сворачивается при клике вне меню, по `Esc` или при потере фокуса. На мобильной ширине меню открывается оверлеем.

### Дерево связок

- Построение дерева из корневых связок и их продолжений.
- Активная ветка (хребет) и стек «братьев», мини-карточки.
- Два режима: «⌨ только активная ветка» и «⊞ все ветви дерева».
- Ответвления (merge): подключение одного узла к другому узлу с той же позицией счёта.
- Панорамирование доски, линии-связи между узлами.
- Изменение/удаление движений на узле, счёт начала и длительность движения.

### Библиотека движений

- Список всех движений: название, число использований в дереве.
- Для каждого движения — описания «Лид» и «Фоллоу».
- Добавление, переименование и удаление движений.
- Кнопка `▶`/`▶N` у движения, если оно встречается в видео комбинаций — показывает все такие видео с местами (восьмёрка и счёт).

### Библиотека препов

- Отдельная библиотека переходов: название, описания «Лид» и «Фоллоу».
- Препы стоят на линиях между движениями, могут объединять несколько продолжений и не занимают счётов.

### Комбинации

- Автоматический сбор всех завершённых путей дерева в готовые комбинации.
- У каждой комбинации — одно или несколько видео (ссылки на Google Диск), просмотр внутри приложения.
- У каждой комбинации — текстовое описание (поддерживает @-упоминания), показывается под последовательностью.
- В последовательности комбинации показаны движения, счёт и отметка «квадрат» (завершение 32 счётов).

### Генератор

- Извлечение паттернов переходов из существующих комбинаций.
- Генерация новых связок длиной ровно в 32 счёта (1 квадрат) из найденных паттернов.
- Дедупликация против уже существующих комбинаций.
- Разворот выбранной сгенерированной связки в дерево связок.
- При изменении движений, структуры дерева или импорте результаты очищаются; переключение разделов и ручная раскладка их сохраняют.

### Словарь

- Библиотека понятий: сокращённое наименование (уникальное), варианты полного названия, развёрнутое текстовое описание, вложенные ссылки на картинки и видео.
- `id` понятия — стабильный буквенно-цифровой код (`w1`, `w2`, …), не зависящий от сокращения.
- В определении можно использовать @-упоминания других понятий (гиперссылки).
- При удалении понятия показываются места использования и предлагается замена (другим понятием или текстом).

## @-упоминания (гиперссылки)

В любом текстовом поле (название движения, «Лид», «Фоллоу», определение понятия):

- Введите `@` — откроется окно поиска понятия.
- Поиск идёт по сокращению и по всем вариантам полного названия.
- Наведите курсор на понятие в списке — появится подсказка с полной информацией.
- Клик по понятию вставляет его сокращённое название как подчёркнутую ссылку.
- Вставленная ссылка удаляется как обычный текст и заменяется повторным вводом `@`.
- При наведении на ссылку в дереве, комбинациях или библиотеке показывается та же подсказка.

## Видео и медиа

- Видео комбинаций — ссылки на файлы Google Диска, проигрываются во встроенном iframe.
- Медиа понятий — ссылки на YouTube (`watch`, `shorts`, `youtu.be`) или Google Диск (картинки и видео), открываются в модальном окне приложения.

## Экспорт / импорт

- «Экспорт всего» — полный бэкап состояния в JSON (движения, дерево, комбинации, словарь, видео).
- «Экспорт комб.» — готовые комбинации в виде списка шагов (движение, счёт, длительность, видео).
- «Импорт» — открывает окно выбора источника: локальный файл (системный диалог выбора файла) или ссылка на JSON (например, на Google Диске). Файл должен содержать поля `movements`, `nodes`, `roots`.
- Перед заменой данных проверяются структура, ссылки, циклы и допустимость счётов. Старые файлы получают недостающие настройки. Ошибка или отмена импорта сохраняет прежние данные.
- Для Google Диска распознаются ссылки вида `/file/d/<id>/view` и `?id=<id>`. Адрес скачивания строится через `drive.usercontent.google.com/download` без учётных данных Google. Drive может блокировать прямой запрос из браузера даже для общедоступного файла: тогда используйте «Скачать файл» → «Выбрать скачанный JSON» в том же окне. Для полностью автоматического чтения Drive нужна отдельная интеграция с Google API или сервер.
- Другой сервер должен отдавать сам JSON и разрешать чтение из приложения (CORS). При сетевой ошибке, закрытом доступе или тайм-ауте 20 секунд доступны скачивание и выбор локального файла. Возврат назад или закрытие окна отменяет загрузку.

## Хранение данных

После входа библиотека хранится в SQLite на сервере, а в браузере — отдельная копия аккаунта. Вход доступен через Google или код из письма, когда соответствующий способ настроен владельцем сервера. Токен сессии находится в HttpOnly cookie.

Без входа гостевые данные сохраняются под ключом `dance-combos-v10`; кэши аккаунтов — под отдельными ключами. При входе гостевая библиотека не загружается в аккаунт автоматически: для нового аккаунта есть явная кнопка переноса. Очистка браузера удаляет локальные данные; серверные данные остаются в аккаунте.

Если запись не удалась, постоянная плашка предлагает экспорт и повторную попытку. Обычные изменения остаются в памяти до закрытия страницы; неудачный импорт откатывается к прежним данным.

## Связь с Google Диском

Дополнительное хранение в Google Drive находится в **Аккаунт и сохранение → Дополнительно: Google Диск**. В серверном режиме фоновое сохранение на Drive выключено, основное хранилище — сервер. В локальной версии прежняя связь с JSON-файлом Drive остаётся доступной. Владелец один раз задаёт браузерные реквизиты в `GOOGLE_DRIVE_CONFIG`; они не нужны для обычного серверного входа Google. [Инструкция запасного варианта](GOOGLE_DRIVE_SETUP.md).

После перезапуска сначала открывается локальная копия. Нажмите **Подключиться**, чтобы получить доступ Google и сверить её с облаком; повторно выбирать файл не нужно. При изменении обеих версий автосохранение приостанавливается до вашего выбора. Истёкший токен или отсутствие интернета не удаляют локальные изменения.

Облачная связь работает на HTTPS (в том числе GitHub Pages) или localhost. OAuth-токены хранятся только в памяти. Основное приложение работает без загрузки Google SDK; они подключаются при открытии окна облака.

## Проверки

`node tests/run-tests.js` запускает проверки в отдельной временной копии и изолированном профиле Chrome. Можно задать `CHROME_PATH`. Для дополнительной проверки своего JSON задайте переменную окружения `DANCE_IMPORT_FIXTURE` с путём к файлу: данные не попадут в репозиторий и не затронут рабочее хранилище браузера.

Сценарии облачной синхронизации находятся в `tests/drive-suite.js` и проверяют ответы Google API на подменённом сервере. Реальный OAuth/Picker и запись в Drive требуют отдельной проверки с настроенным проектом Google Cloud.

Серверные проверки: `cd server && npm ci && npm test`. Сквозная проверка настоящего HTTP API, SQLite и браузера: `node tests/server-browser-smoke.mjs` из корня проекта. Почтовые коды в тестах перехватываются в памяти; реальные письма не отправляются.

## Технологии

Клиент — обычные HTML/CSS/JavaScript без сборщика. Сервер — Node.js, встроенная SQLite, jose для проверки Google ID token и Nodemailer для отправки писем. Развёртывание — Docker Compose и Caddy.
