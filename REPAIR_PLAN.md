# План исправлений импорта и хранения

1. **Общая подготовка состояния.** Проверять структуру библиотек и узлов, идентификаторы, ссылки на движения и родителей, циклы дерева. Восстанавливать roots/nodeOrder, счётчики и отсутствующие настройки. Использовать один путь подготовки при загрузке и импорте; функции ранней загрузки держать в state.js.
2. **Безопасный импорт.** Разбирать и нормализовать отдельный объект до подтверждения и замены state. Проверять доменные правила счёта. Не менять текущие данные при ошибке или отмене. При ошибке сохранения/рендера восстанавливать прежнее состояние. Обрабатывать ошибку чтения локального файла; закрывать окно только после успеха.
3. **Ошибка сохранения.** Возвращать результат из saveState, показывать постоянную плашку с экспортом и повторной попыткой. Убирать её только после успешной записи. Проверить отказ localStorage и восстановление записи.
4. **Генератор.** Сбрасывать результаты при импорте и изменении исходных движений/узлов/переходов. Не сбрасывать при переключении разделов и изменении раскладки. Перед добавлением проверять наличие всех движений и корректность счёта.
5. **Импорт по ссылке.** Заменить неработающий Drive /uc на проверенный /download у drive.usercontent.google.com. Поддержать resourcekey. Ограничить URL протоколами HTTP(S), добавить тайм-аут и отмену при закрытии/возврате, исключить повторные запросы и применение запоздалых ответов. Различать HTML вместо JSON, HTTP-ошибки и сетевой отказ; дать скачивание и выбор файла как запасной путь.
6. **Проверки.** Добавить регрессионные сценарии в tests/test-suite.js, включая подменённый fetch и ошибку хранилища. Прогнать весь набор и node --check. Отдельно проверить реальный пользовательский файл в изолированной копии; проверить ширины 1400, 900 и 390 px.
7. **Документация и доставка.** Обновить README (шесть разделов, ограничения URL и сообщения сохранения), убрать исправленные пункты из AGENTS.md. Синхронно поднять APP_VERSION, meta и все версии ресурсов. Коммит и публикация — только по отдельному запросу.

Диагностика 12 ноября 2026: исходный Drive /uc отвечает 403 без CORS. drive.usercontent.google.com/download отвечает обычному HTTP-клиенту 200 с Access-Control-Allow-Origin: *, файл побайтово совпадает с локальным (SHA-256). Но реальный браузерный запрос с Sec-Fetch-Mode: cors / Sec-Fetch-Site: cross-site получает 403 без CORS. Поэтому прямое чтение Drive остаётся внешним ограничением: реализован двухшаговый путь скачивания и выбора файла; для автоматизации потребуется интеграция с Google API или сервер. Локальный файл содержит 60 движений и 106 узлов. Эти данные не добавляются в репозиторий.

## Результат

- Пункты 1–4 реализованы; подготовка старого импорта также синхронизирует выбранный режим дерева и закрепление меню.
- Пункт 5 реализован для обычных CORS-совместимых JSON-адресов; для Drive реализованы распознавание ссылки, адрес скачивания, объяснение отказа и выбор скачанного JSON. Автоматический прямой импорт с данного Drive-адреса блокируется Google, это не устранено сменой URL.
- Пункт 6: 143 автоматические проверки без персонального файла, 144 с ним. Дополнительно настоящий FileReader и импорт пользовательского JSON проверены в отдельном Chrome на ширинах 1400, 900 и 390 px: все шесть разделов, оба режима дерева, сохранение, отсутствие горизонтального переполнения и доступность элементов окна импорта. Скриншоты проверены на десктопе и телефоне. Реальный сетевой отказ Drive подтверждён в Chrome и HTTP-запросом с браузерными заголовками.
- Пункт 7: README и AGENTS.md обновлены, версия ресурсов — 2026-11-12.1. Коммит и публикация не выполнялись.

## Дополнение: связь с облачным файлом без сервера

По уточнённому запросу добавлена кнопка «☁ Google Диск»: GIS OAuth с разрешением `drive.file`, выбор JSON через Google Picker, запоминание файла, автосохранение и сверка версий, разрешение конфликтов, сохранение локальных изменений при потере сети или истечении доступа. Общие браузерные реквизиты задаются владельцем приложения один раз в `GOOGLE_DRIVE_CONFIG`, пользователи вводят только разрешение через Google. Ссылка сама по себе не выдаёт право записи.

Настройка: `GOOGLE_DRIVE_SETUP.md`. Тесты: `tests/drive-suite.js`. Версия ресурсов — 2026-11-12.2. Настоящие OAuth/Picker и изменение файла Drive пока не проверены: требуются реквизиты настроенного Google Cloud проекта и вход владельца аккаунта. Модуль не отправляет запросов к Drive без пользовательской авторизации.

## Основное серверное хранилище

По следующему уточнению основной вариант изменён на собственный сервер. Реализованы Node.js/SQLite, Google OIDC и email-коды, HttpOnly-сессии, изолированные библиотеки, раздельные локальные кэши, автосохранение и атомарные revision-конфликты, история и резервная копия базы. Google Drive перенесён в дополнительные функции.

Для Ubuntu 24.04 подготовлены Docker Compose и Caddy, домен `dance-sequence-builder.duckdns.org` соответствует заданному IP `78.17.57.32`. Инструкция — `SERVER_SETUP.md`. Версия ресурсов — 2026-11-12.3. SMTP пока не задан, Google-вход также требует серверных реквизитов владельца. Рабочие секреты не включаются в Git и Docker-образ.

## Развёртывание и GitHub Actions

VPS доступен по указанному владельцем SSH-ключу. Контейнер запущен на localhost:8088, домен подключён к существующему nginx, HTTPS-сертификат выпущен Certbot. На сервере проходят все серверные тесты, публичный health API доступен.

Добавлен workflow master push → проверки → VPS → Pages. Подготовлены ограниченный deploy-ключ, секреты окружения production и ограничение веткой master. Pages переведён на Actions. Клиент Pages обращается к API VPS: CORS + bearer без сторонних cookie, Google return-code с PKCE. Версия ресурсов — 2026-11-13.1. Публикация workflow коммитом/push требует отдельной явной команды согласно AGENTS.md.
